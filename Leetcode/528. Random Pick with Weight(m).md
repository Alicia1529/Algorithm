**Boundary cheat sheet** — this is `bisect_right` on the prefix-sum array (find the
*first* prefix > candidate). The variant I keep tripping on:

```python
# candidate ∈ [0, total-1].  Want first index where presum[idx] > candidate.
l, h = 0, len(self.presum) - 1   # search within valid indices (h = n-1, NOT n)
while l < h:                     # half-open: loop exits when l == h, no <=
    mid = (l + h) // 2           # floor → biased low → pairs with `l = mid+1`
    if self.presum[mid] <= candidate:
        l = mid + 1              # mid can't be the answer → exclude it
    else:
        h = mid                  # mid MIGHT be the answer → keep it (don't -1)
return l
```

Why it's correct / the traps:
- Use `candidate = randint(0, total-1)` (NOT `randint(1, total)`) so it pairs with
  `<=` and `bisect_right`. With `presum` ending at `total`, `candidate` never exceeds the
  last bucket, so `l` never runs off the end → `h = n-1` is safe.
- `l < h` (not `l <= h`): with `h = mid` on the else-branch, `<=` would loop forever when
  `l == h == mid`. The two consistent styles are: **`l < h` + `h = mid`** (answer-keeping)
  OR **`l <= h` + `h = mid - 1`** (answer-excluding, return `l`). Don't mix them.
- The asymmetry is the whole point: `l = mid + 1` (exclude) vs `h = mid` (keep). Whichever
  side *could still hold the answer* must NOT move past `mid`.
