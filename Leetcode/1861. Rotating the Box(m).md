tag: matrix, two pointers, simulation, gravity

`#` 是石头、`*` 是固定障碍、`.` 是空格。把箱子顺时针旋转 90°，然后让石头受重力下落
到底（被障碍或其他石头挡住就停）。返回旋转并沉降后的箱子。

**两个独立的子问题：旋转 + 沉降。** 顺序可以任选，这决定了重力的方向：

| 顺序 | 重力方向 | 心智负担 |
|---|---|---|
| 先旋转，再沉降 | 向**下**（直觉） | 要在旋转后的坐标系里思考 |
| 先沉降，再旋转 | 向**右**（原坐标系） | 不用换坐标系，代码更短 |

### Python — 1. 先旋转，再沉降

```python
class Solution:
    def rotateTheBox(self, boxGrid: List[List[str]]) -> List[List[str]]:
        m, n = len(boxGrid), len(boxGrid[0])
        output = [['.'] * m for _ in range(n)]

        # 顺时针旋转 90°：原 (i, j) -> 新 (j, m-1-i)
        for i in range(m):
            for j in range(n):
                output[j][m - 1 - i] = boxGrid[i][j]

        # 每列从底往上沉降
        for col in range(m):
            last_row = n - 1                      # 下一个石头该落在哪
            for row in range(n - 1, -1, -1):
                if output[row][col] == '.':
                    continue
                if output[row][col] == '*':
                    last_row = row - 1            # 障碍物重置落点
                    continue
                output[row][col] = '.'            # ← 必须清空源格子
                output[last_row][col] = '#'
                last_row -= 1
        return output
```

**O(m·n) 时间，O(m·n) 空间**（输出矩阵本身）。

### Python — 2. 先沉降，再旋转（更短）

在原矩阵里让每行石头靠右，然后一次旋转收工。

```python
class Solution:
    def rotateTheBox(self, boxGrid: List[List[str]]) -> List[List[str]]:
        m, n = len(boxGrid), len(boxGrid[0])

        for i in range(m):                        # 重力向右
            write = n - 1
            for j in range(n - 1, -1, -1):
                if boxGrid[i][j] == '*':
                    write = j - 1
                elif boxGrid[i][j] == '#':
                    boxGrid[i][j] = '.'
                    boxGrid[i][write] = '#'
                    write -= 1

        return [[boxGrid[m - 1 - i][j] for i in range(m)] for j in range(n)]
```

> 旋转公式：顺时针 `new[j][m-1-i] = old[i][j]`，逆时针 `new[j][i] = old[i][n-1-j]`。
> 非方阵时结果是 `n × m`，别写成 `m × n`。

### ⚠️ 核心陷阱：搬石头必须清空源格子

少写 `output[row][col] = '.'` 这一行，石头会被**复制**而不是移动。

最小反例 `boxGrid = [['*', '#', '.']]`（1×3）：

```
错误输出: [['*'], ['#'], ['#']]    ← 两个 #
正确答案: [['*'], ['.'], ['#']]    ← 一个 #
```

旋转后那一列是 `['*', '#', '.']`，自底向上走：

| row | 字符 | 动作 |
|---|---|---|
| 2 | `.` | 跳过，`last_row` 保持 2 |
| 1 | `#` | 写到 row 2，`last_row → 1`。**源格子 row 1 没清空** |
| 0 | `*` | `last_row = -1` |

结束时 `last_row = -1`，所以结尾那个补 `.` 的 `while` 一次都没跑，row 1 的残留 `#`
留下来了。

### 和 [723. Candy Crush](<723. Candy Crush(m).md>) 的 drop 差在哪

两题的沉降循环写法几乎一样，但 **723 可以不清空源格子，1861 必须清空**。原因是
障碍物破坏了一个不变量：

**723（无障碍）：`last_row <= row` 恒成立。**
写指针和读指针都从底部出发，读指针每步 `-1`、写指针只在写入时 `-1`，所以读指针跑得
至少一样快 —— 写入位置**永远是已经读过的格子**。残留全部集中在 `[0, last_row]`，被
结尾的补零循环一次性清掉。那个补零循环是**真正的清理工**。

```python
# 723：补零循环在干实事
while last_row >= 0:
    board[last_row][col] = 0     # 把上方所有残留清掉
    last_row -= 1
```

**1861（有障碍）：`*` 让 `last_row` 跳到障碍物上方，不变量失效。**
障碍物把一列切成多个独立区段，每段有自己的落点起点。残留可能留在**任意区段内部**
（如上面 row 1 那个 `#`），而不只是列顶部 —— 所以事后统一填充覆盖不到，必须在搬运
时就地清空。

| | 723 Candy Crush | 1861 Rotating the Box |
|---|---|---|
| 障碍物 | 无 | 有（`*`） |
| 写指针 | 单调 `-1`，`last_row <= row` 恒成立 | 遇 `*` 跳到障碍物上方 |
| 残留位置 | 只在列顶部 `[0, last_row]` | 可能在任意区段内部 |
| 清理方式 | 结尾统一补零 ✅ | 必须逐格清空源格子 ✅ |
| 不清源格子 | 安全 | **石头被复制** ❌ |

> **补充：清空源格子之后，结尾那个 `while last_row >= 0: … = '.'` 就变成 no-op 了。**
> 删掉是为了精简，不是因为有 bug。`last_row` 只会在两种时候移动：放下石头后 `-1`
> （源格子已清空），或撞到 `*` 时跳到**障碍物上方**。所以 `[0, last_row]` 这个范围
> 永远到不了障碍物下方，填充只会把 `.` 写成 `.`。实测 40,000 个列：循环结束时
> `[0, last_row]` 内没有任何一格不是 `.`。

### 归纳：同类题的三个套路

#### 套路 A：写指针压缩（重力 / 移除元素）

**一个读指针扫、一个写指针落**，是本题沉降的本质，也是整个"原地重排"家族的共同骨架：

```python
write = <起点>
for read in <扫描顺序>:
    if <该保留>:
        arr[write] = arr[read]
        write += <步长>
# 可选：用默认值填充 write 之后的位置
```

| 题 | 读/写方向 | 保留条件 | 本仓库 |
|---|---|---|---|
| [27. Remove Element](<27. Remove Element(e).md>) | 左→右 | `!= val` | ✓ |
| [26. Remove Duplicates](<26. Remove Duplicates from Sorted Array(e).md>) | 左→右 | `!= nums[write-1]` | ✓ |
| [80. Remove Duplicates II](<80. Remove Duplicates from Sorted Array II(m).md>) | 左→右 | `!= nums[write-2]` | ✓ |
| [283. Move Zeroes](<283. Move Zeroes(e).md>) | 左→右 | `!= 0` | ✓ |
| [88. Merge Sorted Array](<88. Merge Sorted Array(e).md>) | **右→左** | 取两者较大 | ✓ |
| [723. Candy Crush](<723. Candy Crush(m).md>) | 下→上（逐列） | `!= 0` | ✓ |
| **1861. Rotating the Box** | 下→上（逐列） | `== '#'`，遇 `*` 重置 | ✓ |

> **为什么 88 要反着走**：那题的空位在**尾部**，正向填充会覆盖还没读的数据。方向选
> 「从空位那一端开始」是这个套路的通用判断法 —— 1861 的空位在底部（重力方向），所以
> 自底向上。

#### 套路 B：分段处理（障碍物把结构切块）

障碍物 = 区段分隔符。核心动作是**撞到分隔符就重置写指针**，每段独立处理：

```python
if cell == OBSTACLE:
    write = <该段新起点>     # 重置，不是继续
```

| 题 | 分隔符 | 本仓库 |
|---|---|---|
| **1861. Rotating the Box** | `*` 障碍物 | ✓ |
| [75. Sort Colors](<75. Sort Colors(m).md>) | 三值分区（荷兰国旗） | ✓ |
| 2465. Number of Distinct Averages | 无，但同为双端收缩 | — |

这一类的通病就是本题的陷阱：**跨段搬运时忘记清空源格子**。单段（无障碍）时事后统一
填充能兜住，多段时兜不住。

#### 套路 C：矩阵旋转 / 转置

| 题 | 操作 | 公式 | 本仓库 |
|---|---|---|---|
| [48. Rotate Image](<48. Rotate Image(m).md>) | 方阵原地顺时针 | 转置 + 每行 reverse | ✓ |
| **1861. Rotating the Box** | 非方阵顺时针 | `new[j][m-1-i] = old[i][j]` | ✓ |
| [54. Spiral Matrix](<54. Spiral Matrix(m).md>) | 螺旋遍历 | 四边界收缩 | ✓ |
| 867. Transpose Matrix | 转置 | `new[j][i] = old[i][j]` | — |

> **48 能原地做是因为它是方阵**（转置 + reverse 不改变形状）。1861 是 `m × n → n × m`，
> 形状变了，必须新建矩阵。这是「能不能原地」的判断依据。

```c++
// Runtime: 212 ms, faster than 95.53% of C++ online submissions for Rotating the Box.
// Memory Usage: 52.5 MB, less than 75.36% of C++ online submissions for Rotating the Box.

class Solution {
public:
    vector<vector<char>> rotateTheBox(vector<vector<char>>& box) {
        int m = box.size();
        int n = box[0].size();
        vector<vector<char>> ret(n, vector<char>(m, '.'));
        
        for (int c = m - 1; c >= 0; c--) {
            int i = n - 1;
            for (int r = n - 1; r >= 0; r--) {
                if (box[m - c - 1][r] == '*') {
                    ret[r][c] = '*';
                    i = r - 1;
                    
                } else if (box[m - c - 1][r] == '#') {
                    ret[i][c] = '#';
                    i--;
                }
            }
        }
        return ret;
        
    }
};



class Solution {
public:
    vector<vector<char>> rotateTheBox(vector<vector<char>>& box) {
        int m = box.size();
        int n = box[0].size();
        vector<vector<int>> stones;
        vector<vector<int>> obs;
        for (auto& row: box) {
            vector<int> s, o;
            int num = 0;
            for (int i = 0; i < row.size(); i++) {
                if (row[i] == '*') {
                    o.push_back(i);
                    s.push_back(num);
                    num = 0;
                } else if (row[i] == '#') {
                    num++;
                }
            }
            s.push_back(num);
            stones.push_back(s);
            obs.push_back(o);
        }
        vector<vector<char>> ret(n, vector<char>(m, '.'));
        
        for (int c = m - 1; c >= 0; c--) {
            for (int r = n - 1; r >= 0; r--) {
                if (obs[m - c - 1].size() && obs[m - c - 1].back() == r) {
                    ret[r][c] = '*';
                    obs[m - c - 1].pop_back();
                    stones[m - c - 1].pop_back();
                } else if (stones[m - c - 1].back()) {
                    ret[r][c] = '#';
                    stones[m - c - 1].back()--;
                }
            }
        }
        return ret;
        
    }
};
```
