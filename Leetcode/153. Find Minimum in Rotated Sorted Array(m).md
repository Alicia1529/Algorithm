### Python
```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        # Template A: find the first index whose value is <= nums[-1].
        left, right = 0, len(nums) - 1
        while left < right:                 # strict <  → pairs with right = mid
            mid = (left + right) // 2
            if nums[mid] > nums[right]:      # seam is to the RIGHT → min is right
                left = mid + 1
            else:                            # nums[mid] <= nums[right]: mid MIGHT be min
                right = mid                  # keep mid — NOT mid + 1
        return nums[left]                    # left == right == index of min
```
- **Compare against `nums[right]`, not `nums[left]`:** using the right endpoint
  handles a non-rotated array for free (everything is `<= nums[right]`, so it
  converges to index 0). Comparing against `nums[left]` needs a special case.
- **Two boundary rules this problem tests** (both were slips in the first draft):
  `while left < right` **must** pair with `right = mid` (not `mid + 1`), because
  when `nums[mid] <= nums[right]`, `mid` itself could be the minimum — moving past
  it skips the answer.
- O(log n) time, O(1) space. Distinct values assumed (duplicates → LC 154, O(n)).

// O(n)
class Solution {
public:
    int findMin(vector<int>& nums) {
        for (int i = 1; i < nums.size(); i++) {
            if (nums[i] < nums[i - 1]) return nums[i];
        return nums[0];
    }
};

class Solution {
public:
    int findMin(vector<int>& nums) {
        int l = 0;
        int r = nums.size() - 1;
        
        while (l < r) {
            int m = l + (r - l) / 2;
            if (nums[m] > nums.back()) {
                l = m + 1;
            } else {
                r = m;
            }
        }
        return nums[l];
    }
};
