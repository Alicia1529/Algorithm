# 354. Russian Doll Envelopes

tag: dynamic programming, binary search, sorting

1. Sort + O(n log n) LIS

- Sort by width ascending, height **descending** for ties
- Then run LIS on heights only
- The `-height` trick prevents picking two envelopes with the same width: same-width heights appear in decreasing order, so LIS can never select both

```python
class Solution:
    def maxEnvelopes(self, envelopes: List[List[int]]) -> int:
        import bisect
        envelopes.sort(key=lambda x: (x[0], -x[1]))

        def LIS(nums):
            dp = []
            for num in nums:
                idx = bisect.bisect_left(dp, num)
                if idx == len(dp):
                    dp.append(num)
                else:
                    dp[idx] = num
            return len(dp)

        return LIS([e[1] for e in envelopes])
```

- Time: O(n log n) — sort + LIS with binary search
- Space: O(n)

**Why sort height descending for same width:**

```
envelopes with width=6: [6,7], [6,4]
sorted (w asc, h desc): [6,7] → [6,4]   heights: ..., 7, 4, ...
                                                        ↑  ↑
                                                    decreasing → LIS skips one
```

If heights were ascending (7 → 4 flipped), LIS could pick both → wrong answer.

**LIS via patience sorting (`dp` array):**

- `dp[i]` = smallest tail of any IS of length `i+1`
- `bisect_left` finds first position where `dp[pos] ≥ num`
  - `pos == len(dp)` → append (new longest length found)
  - `pos < len(dp)` → replace (smaller tail = better for future extensions)
- `dp` is always sorted; only `len(dp)` is meaningful (contents may not form a valid subsequence)
