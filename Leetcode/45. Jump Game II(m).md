tag: dynamic programming / greedy algorithm

Minimum number of jumps to reach the last index. Guaranteed reachable.

### Python

**Greedy — BFS by levels, flattened into one pass**

```python
class Solution:
    def jump(self, nums: List[int]) -> int:
        n = len(nums)
        jumps = 0
        current_end = 0   # farthest index reachable with "jumps" jumps so far
        farthest = 0      # farthest index reachable with one more jump
        for i in range(n - 1):   # stop before last — arriving needs no new jump
            farthest = max(farthest, i + nums[i])
            if i == current_end:
                jumps += 1
                current_end = farthest
        return jumps
```

O(n) time, O(1) space.

**The idea:** this is breadth-first search without the queue. `current_end` is the
end of the current BFS level — every index in `[prev_end+1 .. current_end]` is
reachable in exactly `jumps` jumps. While scanning that window you compute
`farthest`, the reach of the *next* level. Hitting `i == current_end` means the level
is exhausted: pay one jump and open the next window.

```
nums = [2,3,1,1,4]
level 0: {0}        farthest = 2
level 1: {1,2}      farthest = max(1+3, 2+1) = 4   → jumps = 1
level 2: {3,4}      contains n-1 = 4               → jumps = 2
```

**Why `range(n - 1)` and not `range(n)`:** arriving at the last index costs nothing.
If the loop reached `i = n-1` and that index happened to be a level boundary, you'd
increment `jumps` for a jump you never take. With `n = 1` the loop body never runs
and you correctly return 0.

> **The relationship to [55. Jump Game](<55. Jump Game(m).md>):** identical scan,
> different question. 55 asks *can* you reach the end — track one frontier and fail
> if it falls behind `i`. 45 asks *how few* jumps — track two frontiers (`current_end`
> for this level, `farthest` for the next) and count the level closures.

### C++

Greedy Algorithm
```c++
// Runtime: 12 ms, faster than 83.74% of C++ online submissions for Jump Game II.
// Memory Usage: 16.3 MB, less than 56.63% of C++ online submissions for Jump Game II.
class Solution {
public:
    int jump(vector<int>& nums) {
        int jumps = 0, curr = 0, farthest = 0;
        // take care of the -1 here
        for (int i = 0; i < nums.size() - 1; i++) {
            farthest = max(farthest, i + nums[i]);
            if (curr == i) {
                jumps++;
                curr = farthest;
            }
        }
        return jumps;
        
    }
};
```
> **What the `-1` comment is about:** `nums.size()` is `size_t` (unsigned), so
> `nums.size() - 1` wraps to `SIZE_MAX` when the vector is **empty** — the loop then
> runs away and reads out of bounds. `i` being `int` doesn't save you; the comparison
> promotes `i` to unsigned. LeetCode guarantees `n >= 1` so this code is safe as
> written (size 1 gives plainly `0` and the loop skips), but reused on a possibly
> empty vector it needs `i + 1 < nums.size()`. Python's `range(n - 1)` has no such
> problem — `range(-1)` is just empty.

Dynamic Programming
```c++
// Runtime: 404 ms, faster than 16.52% of C++ online submissions for Jump Game II.
// Memory Usage: 17 MB, less than 11.38% of C++ online submissions for Jump Game II.
class Solution {
public:
    int jump(vector<int>& nums) {
        vector<int> memo(nums.size(), INT_MAX);
        memo[0] = 0;
        
        for (int i = 0; i < nums.size(); i++) {
            if (memo[i] == INT_MAX) continue;
            for (int j = 1; j <= nums[i] && i + j < nums.size(); j++) {
                memo[i + j] = min(memo[i + j], memo[i] + 1);
            }
        }
        return memo[nums.size() - 1];
        
    }
};
```
> O(n·max(nums)) — every index re-scans its whole jump range. The greedy collapses
> that inner loop into a running `max`, which is the entire difference between 404 ms
> and 12 ms.
