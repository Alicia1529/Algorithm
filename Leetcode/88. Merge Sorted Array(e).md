## Python — fill from the back, O(m+n) time / O(1) space

**Key trick:** `nums1` has `n` spare slots at the end, so write the **largest**
element into the back and walk both pointers backward. Filling back-to-front means
you never overwrite a `nums1` value you haven't read yet.

```python
class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        """Do not return anything, modify nums1 in-place instead."""
        i, j, k = m - 1, n - 1, m + n - 1   # tails of nums1, nums2, and the write head
        while 0 <= i and 0 <= j:
            if nums1[i] < nums2[j]:
                nums1[k] = nums2[j]; j -= 1
            else:
                nums1[k] = nums1[i]; i -= 1
            k -= 1
        while 0 <= j:                        # drain leftover nums2 into the front
            nums1[k] = nums2[j]; j -= 1; k -= 1
```

- **No leftover-`nums1` loop needed:** if `nums2` empties first, the remaining
  `nums1` elements are already in their correct positions — leave them.
- **Why fill backward:** the write head `k` is always `≥ i`, so each write lands in
  a slot whose original value has already been consumed → safe in-place merge.

**Complexity:** O(m+n) time, O(1) extra space.
