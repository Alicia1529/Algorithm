tag: hash table, union find

**Key insight:** dump everything into a set for O(1) lookup, then only start counting from a
**sequence start** — a number `num` where `num - 1` is NOT in the set. This guard is what
keeps it O(n): each number is the inner `while` walk's target at most once across the whole
run, so the total work is linear, not O(n·length).

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        ret = 0
        d = set(nums)
        for num in d:
            if num - 1 not in d:          # only count from a sequence start
                cnt = 0
                while num + cnt in d:     # walk the run upward
                    cnt += 1
                ret = max(ret, cnt)
        return ret
```

**Complexity:** O(n) time, O(n) space. Sorting would be O(n log n) — the set + start-guard
trick is what beats it.

> ⚠️ The trap: without the `if num - 1 not in d` guard you'd re-walk every run from every
> element → O(n·length), effectively O(n²). The guard ensures each run is walked exactly once.
