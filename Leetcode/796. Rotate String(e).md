tag: string, string matching, KMP

判断 `goal` 是否能由 `s` 循环左移若干位得到。`1 <= n <= 100`。

### 核心洞察

**`goal` 是 `s` 的旋转 ⟺ `goal` 是 `s + s` 的子串（且两者等长）。**

`s + s` 把 `s` 的全部 `n` 个旋转都作为连续子串包含进来了：

```
s = "abcde"
s + s = "abcdeabcde"
         abcde          ← 偏移 0
          bcdea         ← 偏移 1
           cdeab        ← 偏移 2
            deabc       ← 偏移 3
             eabcd      ← 偏移 4
```

长度检查不能省 —— 否则 `s="abc"`、`goal="ab"` 会被误判为 True。

### Python — 1. 朴素串匹配（虚拟旋转）

对每个偏移 `i` 逐位比较，用 `(i + j) % n` **虚拟**旋转，不真的构造字符串。

```python
class Solution:
    def rotateString(self, s: str, goal: str) -> bool:
        if len(s) != len(goal):
            return False
        n = len(s)
        for i in range(n):
            can_achieve = True
            for j in range(n):
                idx = (i + j) % n
                if goal[j] != s[idx]:
                    can_achieve = False
                    break
            if can_achieve:
                return True
        return False
```

**O(n²) 最坏，O(1) 空间。**

- **`(i + j) % n` 避免了内存分配** —— 比 `s[i:] + s[:i] == goal` 好，后者每轮新建一个
  字符串。空间从 O(n) 降到 O(1)。
- **提前 `break`** 让平均情况远好于最坏。
- ⚠️ **这不是 KMP**。偏移 `i` 失败后，`i+1` 从 `j=0` **重新开始**比较，已匹配的信息
  全部丢弃 —— 这正是 KMP 要改进的基线算法，教科书里叫 naive / brute-force string
  matching。

最坏输入是 `s = "aaa…a"`、`goal = "aaa…ab"`：每个偏移都要走到最后一位才失败。

| n | 实际比较次数 | n² |
|---|---|---|
| 10 | 100 | 100 |
| 100 | 10,000 | 10,000 |
| 1000 | 1,000,000 | 1,000,000 |

题目限制 `n <= 100`，也就是一万次操作 —— 瞬间完成，**这版完全能过**。

### Python — 2. 一行：`goal in s + s`

```python
class Solution:
    def rotateString(self, s: str, goal: str) -> bool:
        return len(s) == len(goal) and goal in s + s
```

**O(n) 典型 / O(n²) 理论最坏，O(n) 空间**（`s + s` 的拷贝）。

CPython 的 `str.__contains__` 用 Crochemore-Perrin 双向算法配合
Boyer-Moore-Horspool 坏字符跳跃，跑在 C 层。实测比写法 1 快约 **40x**。

> 面试里这是期望答案：说出 `s + s` 的洞察，写这一行，然后主动补「如果不让用内置
> 子串搜索，我可以手写 KMP 保证 O(n) 最坏」。

### Python — 3. KMP（真正的 O(n) 最坏保证）

```python
class Solution:
    def rotateString(self, s: str, goal: str) -> bool:
        if len(s) != len(goal):
            return False
        if not s:
            return True

        pattern, text = goal, s + s
        n = len(pattern)

        # lps[i] = pattern[:i+1] 的最长 border（既是真前缀又是真后缀）长度
        lps = [0] * n
        k = 0
        for i in range(1, n):
            while k and pattern[i] != pattern[k]:
                k = lps[k - 1]          # 回退到更短的 border
            if pattern[i] == pattern[k]:
                k += 1
            lps[i] = k

        # 在 text 中搜 pattern，文本指针永不回退
        k = 0
        for ch in text:
            while k and ch != pattern[k]:
                k = lps[k - 1]          # 模式指针回退，文本指针不动
            if ch == pattern[k]:
                k += 1
                if k == n:
                    return True
        return False
```

**O(n) 时间，O(n) 空间。**

**KMP 和写法 1 的本质区别：失配时不丢弃已匹配的信息。**

`lps[i]` 是 `pattern[:i+1]` 的最长 border（既是真前缀又是真后缀的那一段）长度：

```
lps('aabaaab') = [0, 1, 0, 1, 2, 2, 3]
lps('abcde')   = [0, 0, 0, 0, 0]        ← 无重复结构，退化成逐位扫
lps('aaaa')    = [0, 1, 2, 3]
```

失配时 `k = lps[k-1]` 把模式指针滑到「已匹配部分的最长 border」，因为那一段**必然**
也和文本对齐 —— 所以**文本指针从不后退**。这就是 O(n) 的来源。

同样的对抗输入，实测对比：

| n | 朴素比较次数 | KMP 文本步数 | KMP 内层回退 | KMP 总计 |
|---|---|---|---|---|
| 10 | 100 | 20 | 11 | 31 |
| 100 | 10,000 | 200 | 101 | 301 |
| 1000 | **1,000,000** | 2,000 | 1,001 | **3,001** |

文本指针恰好走 `2n` 步（就是 `len(s + s)`），总工作量线性。

### 性能实测

n=100（题目上限），每组 300 对，best of 5：

| 场景 | 朴素 O(n²) | `in s+s` | 切片旋转 | KMP |
|---|---|---|---|---|
| 随机串 | 10.03ms | **0.23ms** | 6.71ms | 11.45ms |
| 真旋转 | 6.56ms | **0.14ms** | 2.58ms | 9.72ms |
| 对抗 `aaa…a` / `aaa…b` | 12,145.97ms* | **0.44ms** | 51.28ms | 66.59ms |

\* 该行用 n=1000 测得（超出题目约束），用来暴露 O(n²)。

**反直觉的一点：KMP 在 Python 里反而最慢** —— 理论 O(n) 的优势被解释器开销吃掉了，
而 `in` 虽然理论最坏 O(n²) 却跑在 C 层。所以 KMP 只在面试官明确要求「不用内置搜索、
给出 O(n) 最坏保证」时才值得写。

### 边界差异

空串上三者不一致（题目保证 `n >= 1`，所以都能过）：

| 写法 | `s=""`, `goal=""` |
|---|---|
| 朴素 | `False`（`range(0)` 不进循环） |
| `in s + s` | `True` |
| KMP | `True`（显式 `if not s: return True`） |

严格说空串旋转后还是空串，`True` 更正确。复用这段代码到别处时要注意。
