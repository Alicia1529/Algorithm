Three approaches, in priority order for interviews. See `Collections/Binary Search.md`
Shape 4 for the "count vs. index" (个数 vs 下标) rule behind every ±1 in approach 1.

### Python — Approach 1: partition binary search (OPTIMAL, O(log(min(m,n))))

Binary-search the *cut position* `i` on the shorter array; `j = half - i` is forced.
This is what the problem is actually testing.

```python
class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        if len(nums1) > len(nums2):                # always search the SHORTER array
            nums1, nums2 = nums2, nums1
        m, n = len(nums1), len(nums2)
        half = (m + n + 1) // 2                     # SIZE of the combined LEFT half
        lo, hi = 0, m                              # cut position i ∈ [0, m] inclusive
        while lo <= hi:
            i = (lo + hi) // 2                      # cut nums1 after i elements
            j = half - i                           # cut nums2 after j elements (forced)
            left1  = nums1[i-1] if i > 0 else float('-inf')
            right1 = nums1[i]   if i < m else float('inf')
            left2  = nums2[j-1] if j > 0 else float('-inf')
            right2 = nums2[j]   if j < n else float('inf')
            if left1 <= right2 and left2 <= right1:            # valid partition
                if (m + n) % 2:                                # odd → median in left
                    return max(left1, left2)
                return (max(left1, left2) + min(right1, right2)) / 2
            elif left1 > right2:                    # i too far right
                hi = i - 1
            else:                                   # i too far left
                lo = i + 1
```

- `i`,`j`,`half` are all **counts** → `j = half - i` needs no ±1.
- `hi = m` (not `m-1`): `i` is a cut *position*; a length-`m` array has `m+1` cuts.
- `half = (m+n+1)//2` (not `(m+n)//2`): count = median index + 1; the `+1` puts the
  middle element in the left half on odd totals, so `max(left1,left2)` is the median.
- `nums1[i-1]`/`nums2[j-1]` use `-1`: the only count→index conversion (i-th element
  is at index i-1).

### Python — Approach 2: kth-smallest, divide & conquer (simpler to REASON about)

No `left/right/±inf` bookkeeping — one rule: "compare the k/2-th of each, drop the
smaller half." Easier to remember if the partition invariant feels slippery.

```python
class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        def kth(a, b, k):                    # k-th smallest, 1-indexed
            if len(a) > len(b):
                a, b = b, a                  # a is the shorter
            if not a:
                return b[k-1]
            if k == 1:
                return min(a[0], b[0])
            i = min(k // 2, len(a))          # drop i from a ...
            j = k - i                        # ... or j from b
            if a[i-1] <= b[j-1]:
                return kth(a[i:], b, k - i)  # a's first i are too small → discard
            else:
                return kth(a, b[j:], k - j)

        total = len(nums1) + len(nums2)
        if total % 2:
            return kth(nums1, nums2, total // 2 + 1)
        return (kth(nums1, nums2, total // 2) +
                kth(nums1, nums2, total // 2 + 1)) / 2
```

- Concept is cleaner, but even totals call `kth` twice, and `a[i:]` slicing adds
  overhead (strict O(log) would pass indices instead of slicing).

### Python — Approach 2b: kth-smallest with INDICES (true O(log), no slicing)

Same "drop the smaller k/2 half" idea, but carry start pointers `s1`/`s2` instead of
slicing → no per-call allocation.

```python
class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        m, n = len(nums1), len(nums2)

        # k-th smallest (1-indexed) among nums1[s1:] and nums2[s2:]
        def kth(s1, s2, k):
            if s1 >= m:                          # nums1 exhausted → answer in nums2
                return nums2[s2 + k - 1]
            if s2 >= n:                          # nums2 exhausted → answer in nums1
                return nums1[s1 + k - 1]
            if k == 1:
                return min(nums1[s1], nums2[s2])
            i = min(s1 + k // 2 - 1, m - 1)      # probe index, CLAMPED to the end
            j = min(s2 + k // 2 - 1, n - 1)
            if nums1[i] <= nums2[j]:
                return kth(i + 1, s2, k - (i - s1 + 1))   # drop ACTUAL count removed
            else:
                return kth(s1, j + 1, k - (j - s2 + 1))

        total = m + n
        if total % 2:
            return kth(0, 0, total // 2 + 1)
        return (kth(0, 0, total // 2) + kth(0, 0, total // 2 + 1)) / 2
```

- **Three gotchas vs. the slicing version:**
  1. Exhaustion is `s1 >= m` (pointer ran off), answer = `other[start + k - 1]`.
  2. **Clamp** the probe index `min(..., m-1)` — the remaining part may be shorter
     than `k//2`; without the clamp `nums1[i]` goes out of bounds.
  3. Discard **the actual count removed** `k - (i - s1 + 1)`, NOT `k - k//2` — the
     clamp can remove fewer than `k//2`, so subtracting `k//2` drifts `k`.
- Same count-vs-index discipline: `k` and discard count are **counts**; `i,j,s1,s2`
  are **indices** — mixing them is the bug.

### Python — Approach 2c: kth-smallest, ITERATIVE (no copy, no recursion)

Same logic as 2b with the recursion unrolled into a loop — zero slicing *and* zero
call-stack. Just advance `s1`/`s2` and shrink `k` in place.

```python
class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        m, n = len(nums1), len(nums2)

        def kth(k):                              # k-th smallest overall, 1-indexed
            s1 = s2 = 0
            while True:
                if s1 >= m:
                    return nums2[s2 + k - 1]
                if s2 >= n:
                    return nums1[s1 + k - 1]
                if k == 1:
                    return min(nums1[s1], nums2[s2])
                i = min(s1 + k // 2 - 1, m - 1)  # probe index, clamped
                j = min(s2 + k // 2 - 1, n - 1)
                if nums1[i] <= nums2[j]:
                    k -= i - s1 + 1              # shrink k by ACTUAL count dropped
                    s1 = i + 1                   # advance the pointer
                else:
                    k -= j - s2 + 1
                    s2 = j + 1

        total = m + n
        if total % 2:
            return kth(total // 2 + 1)
        return (kth(total // 2) + kth(total // 2 + 1)) / 2
```

- Identical clamp + actual-discard-count rules as 2b; the only change is
  `return kth(...)` recursion → `s1/s2/k` updates inside `while True`.
- Best of the kth-smallest family: O(log(m+n)) time, O(1) extra space.

### C++ — Approach 3: merge-walk (O(m+n), easy but NOT log-time)

Merge until you step to the middle. Intuitive and passes the judge, but it's O(m+n)
— in an interview this is the fallback; you'll be asked for approach 1.

```c++
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        int m = nums1.size(), n = nums2.size();
        int i = 0, j = 0, mid1 = -1, mid2 = -1;
        for (int idx = 0; idx <= (n + m) / 2; idx++) {
            mid1 = mid2;
            if (i < m && j < n) {
                if (nums1[i] <  nums2[j]) {
                    mid2 = nums1[i++];
                } else {
                    mid2 = nums2[j++];
                }
            } else if (i < m) {
                mid2 = nums1[i++];
            } else {
                mid2 = nums2[j++];
            }
        }
        if ((m + n) % 2) {
            return mid2;
        }
        return (mid1 + mid2) / 2.0;
    }
};
```
