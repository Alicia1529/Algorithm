### Python
```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        # nums = [4,5,6,7,0,1,2], target = 0
        # one half of [left..mid..right] is ALWAYS sorted; find it, then
        # check whether target lies inside that sorted half.
        left, right = 0, len(nums) - 1
        while left <= right:                       # Template B: <= pairs with mid-1
            mid = (left + right) // 2
            if nums[mid] == target:
                return mid

            if nums[left] <= nums[mid]:            # left half [left..mid] is sorted
                if nums[left] <= target < nums[mid]:
                    right = mid - 1                # target in the sorted left half
                else:
                    left = mid + 1                 # target in the right half
            else:                                  # right half [mid..right] is sorted
                if nums[mid] < target <= nums[right]:
                    left = mid + 1                 # target in the sorted right half
                else:
                    right = mid - 1                # target in the left half
        return -1
```
- **Why one half is always sorted:** a rotated sorted array is two ascending runs.
  Any `mid` puts the "seam" in exactly one side, so the other side is fully sorted.
- **Boundary note:** use `nums[left] <= nums[mid]` (not `<`). When the window
  narrows to `left == mid`, `<=` still classifies the left half as sorted; with `<`
  it falls through to the else branch — still correct here, but `<=` is the safer
  habit and handles the sorted-half check uniformly.
- O(log n) time, O(1) space. Distinct values assumed (with duplicates → LC 81,
  worst case O(n)).
